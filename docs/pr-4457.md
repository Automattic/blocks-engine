# Preserve boxed empty headings through the empty-paragraph path

Fixes #4457.

## Root cause

Rich-text heading conversion discarded empty content unconditionally, unlike the source-box retention path used by empty paragraphs (#2802). Attribute-targeted `:empty::before` rules also need selector matching and projection onto saved source-identity classes, rather than depending on an attribute that serialization drops.

## Before / after

Before: the empty level-1 heading before “Title” disappeared, losing its authored line box. After: headings with captured geometry or authored box evidence use the existing empty-source paragraph path, preserving heading level, alignment, source identity, and matching projected pseudo-element rules. Attribute-targeted empty paragraphs retain matching projected rules too. Boxless headings remain dropped. The #2868 editor treatment now covers empty headings.

The public-compiler table-driven regression covers the issue fixture's empty heading, empty attribute-targeted paragraph, and boxless heading. It fails against trunk at the empty-heading assertion.

## Gate remediation

The canonical browser contract returned `null` because headless Chrome can dump the DOM without running `requestAnimationFrame`. Its measurement now runs on `load`; `getBoundingClientRect()` forces layout after scrolling, retaining the real-browser sticky-header assertion without relying on a rendering frame.
