# Fix shared app frames on single-route imports

## Summary
Single-route imports with an app-root wrapper now give every generated native template the shared app frame, header and footer. Entry content retains only its own blocks, and all templates reference the same editable parts.

Closes https://github.com/Automattic/blocks-engine/issues/3172

## Root cause
Verified the issue's pointer: extraction correctly identifies wrapped chrome as `inline_shared_shell`, which binds through shell frames rather than `template_slugs`. `hoistInlineShellFrames()` chose a generic frame only from non-entry pages. A single-route import therefore had only a `front-page` frame. Template generation also applied frames only in its post-content branch, before the single-template fallback could overwrite them.

## Fix
Reuse the safely hoisted sole authored route's frame for all generated lifecycle templates through the existing frame map. Apply frames after native lifecycle content generation, preserving query loops, the single title, search and 404 content. Return the existing generic stylesheet source so newly created pages receive the frame's styles. Multi-route frame selection and explicit template surfaces remain unchanged.

Register `tests/contract/single-route-shell-frame.php` in Composer's canonical suite. It embeds the issue's exact reduced HTML and checks every generated template for one header/footer reference, the app frame and content order, native lifecycle content, and no copied chrome or references in entry content.
