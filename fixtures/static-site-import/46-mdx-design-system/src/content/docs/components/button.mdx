The `Button` component triggers an action — submitting a form, opening a dialog,
or confirming a destructive operation. For navigation, use a `Link` styled as a
button instead; a real `<button>` should never change the URL.

## Anatomy

A button is composed of an optional **start icon**, a **label**, and an optional
**end icon**, inside a pressable target that is always at least 40×40px.

## Variants

`variant` controls emphasis; `tone` controls meaning. The two are orthogonal, so
you can have a `soft danger` or an `outline brand`.

<CodePreview code={`<Button variant="solid">Solid</Button>

<Callout type="info" title="One solid per view">
  Reserve the `solid brand` button for the single most important action on a
  screen. Everything else should step down to `soft`, `outline`, or `ghost`.
</Callout>

## Guidelines

<DoDont>
  <Do>Lead with a verb: "Save changes", "Invite member", "Publish".</Do>
  <Dont>Use vague labels like "OK", "Submit", or "Click here".</Dont>
</DoDont>

<DoDont>
  <Do>Place the primary action on the right in a dialog footer.</Do>
  <Dont>Stack two `solid brand` buttons of equal weight side by side.</Dont>
</DoDont>

## Accessibility

- Renders a native `<button>` — focusable, Enter/Space activated, announced as a
  button by screen readers.
- `loading` sets `aria-busy="true"` and disables pointer + keyboard activation so
  the action can't fire twice.
- Focus shows a 2px `--halo-focus-ring` offset by 2px, meeting the 3:1 non-text
  contrast requirement against every surface.
- Icon-only buttons **must** pass an `aria-label`.

<Callout type="danger" title="Don't disable the only path forward">
  A disabled submit button gives no feedback about *why* it's disabled. Prefer
  keeping it enabled and surfacing a validation message on click.
</Callout>
